Analisis Kebutuhan Desain Sistem

Pendahuluan, latar belakang, tujuan, pengguna, dan kebutuhan fungsional & non-fungsional

1.1 Pendahuluan

Dokumen ini merupakan analisis kebutuhan desain sistem untuk Aplikasi Computer Assisted Test (CAT) Ujian Kompetensi Kataloger yang dikelola oleh Pusat Kodifikasi Badan Logistik Pertahanan Kementerian Pertahanan Republik Indonesia (PUSKOD BALOGHAN KEMHAN). Analisis dilakukan berdasarkan kondisi aplikasi yang saat ini telah berjalan secara aktif, mencakup evaluasi fitur eksisting, identifikasi celah (gap), serta rekomendasi pengembangan dan penguatan sistem.

Jabatan Fungsional Kataloger merupakan jabatan karier Pegawai Negeri Sipil (PNS) yang melaksanakan tugas kegiatan kodifikasi materiil pertahanan berdasarkan sistem NATO Stock Number (NSN). Sebagai satu-satunya instansi National Codification Bureau (NCB) di Indonesia, PUSKOD BALOGHAN KEMHAN bertanggung jawab atas standar dan kualitas seluruh kataloger di lingkungan Kemhan dan TNI. Ujian kompetensi menjadi instrumen utama untuk memastikan standar tersebut terpenuhi secara objektif dan terukur.

1.2 Latar Belakang

Sebelum sistem CAT diimplementasikan, proses ujian kompetensi kataloger dilakukan secara konvensional yang mengandung sejumlah kelemahan: potensi subjektivitas penilaian, risiko kebocoran soal, ketidakefisienan administrasi, serta keterbatasan skalabilitas peserta. Kebutuhan akan sistem ujian yang objektif, terstandardisasi, dan dapat diselenggarakan secara bersamaan untuk banyak peserta mendorong pengembangan platform berbasis web ini.

Aplikasi CAT saat ini telah berhasil digunakan dalam penyelenggaraan lebih dari 110 sesi ujian kompetensi dengan ratusan peserta ber-NIP aktual dari berbagai satuan kerja (Satker) di lingkungan Kemhan. Seiring meningkatnya jumlah peserta dan kompleksitas kebutuhan, diperlukan analisis menyeluruh untuk mengidentifikasi area yang perlu diperkuat — terutama dari sisi keamanan data, kelengkapan fitur penilaian essay, dan perlindungan integritas ujian.

Dasar Hukum: Peraturan Menteri Negara Pendayagunaan Aparatur Negara tentang Jabatan Fungsional Kataloger; Peraturan Pemerintah tentang Pegawai Negeri Sipil; STANAG NATO terkait sistem kodifikasi NSN yang menjadi acuan kompetensi teknis.

1.3 Tujuan

Analisis ini bertujuan untuk:

  • Mendokumentasikan kondisi sistem saat ini — mencakup fitur yang sudah berjalan, struktur database aktual, dan alur proses ujian dari login hingga penerbitan nilai.
  • Mengidentifikasi kebutuhan fungsional yang belum terpenuhi — seperti penilaian essay manual, monitoring live peserta, dan fitur anti-kecurangan.
  • Memetakan kerentanan keamanan — termasuk sistem hashing password yang tidak aman (MD5) dan potensi celah SQL injection yang perlu segera ditangani.
  • Memberikan rekomendasi teknis terstruktur — berupa roadmap pengembangan bertahap yang dapat dijadikan acuan tim pengembang dan manajemen PUSKOD BALOGHAN KEMHAN.
  • Menjadi acuan pengujian dan penerimaan sistem (UAT) — dengan skenario uji yang konkret berdasarkan alur aplikasi nyata.
  • Menyediakan kerangka dokumentasi teknis dan user manual — agar sistem dapat dioperasikan, dipelihara, dan dikembangkan secara berkelanjutan.

1.4 Deskripsi Aplikasi Eksisting

Aplikasi Ujian Online PUSKOD BALOGHAN KEMHAN telah beroperasi sebagai platform Computer Based Test (CBT/CAT) untuk uji kompetensi Jabatan Fungsional Kataloger. Sistem dibangun di atas PHP Native dengan database MySQL (db_ujian_online), berjalan di server dengan root di /var/www/html/ujian/.

Nama Resmi: "Pusat Kodifikasi Badan Logistik Pertahanan Kemhan" — Jl. Jati No.1, Pondok Labu, Jakarta Selatan 12450. Menangani ujian kompetensi berbasis NIP untuk kataloger ASN/PNS di lingkungan KEMHAN dan TNI.

3.3 Masalah Teknis Prioritas

Audit kode dan struktur database mengungkap beberapa masalah teknis yang harus ditangani sebelum sistem dikembangkan lebih lanjut. Masalah-masalah ini diurutkan berdasarkan tingkat risiko terhadap keamanan dan integritas data.

KRITIS — MD5 Password: Tabel admin, guru, siswa menyimpan password dengan MD5. MD5 sudah terbukti tidak aman (rainbow tables). Harus dimigrasi ke password_hash($pass, PASSWORD_BCRYPT).
PENTING — SQL Injection: Pola mysqli_real_escape_string() dipakai di beberapa tempat, namun perlu audit menyeluruh. Transisi ke prepared statements (MySQLi bind_param) untuk semua query dengan input user.
PENTING — Charset latin1: Tabel inti pakai latin1 — karakter unicode (nama dengan aksara khusus) bisa corrupt. Perlu migrasi ke utf8mb4 setelah backup penuh.
DESAIN — Soal Terikat ke Sesi: Kolom soal.id_ujian berarti soal hanya bisa dipakai satu sesi. Untuk bank soal reusable, perlu tabel relasi terpisah ujian_soal.

3.4 Query Migrasi yang Disarankan

Berikut adalah perintah SQL dan perubahan kode PHP yang dapat langsung dieksekusi oleh pengembang untuk menerapkan perbaikan yang diprioritaskan. Lakukan backup penuh sebelum menjalankan perintah ALTER TABLE.

-- 1. Migrasi password ke bcrypt (di login.php dan form create user)
-- GANTI:
$password = md5($_POST['password']);
-- MENJADI:
$password = password_hash($_POST['password'], PASSWORD_BCRYPT);
-- VERIFIKASI LOGIN:
password_verify($_POST['password'], $row['password'])

-- 2. Migrasi charset tabel kritis (jalankan setelah backup penuh!)
ALTER TABLE siswa  CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE guru   CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE admin  CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE ujian  CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE hasil  CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE nilai  CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 3. Tambah kolom tingkat kesulitan soal
ALTER TABLE soal ADD COLUMN tingkat_kesulitan
  ENUM('mudah','sedang','sulit') DEFAULT 'sedang';

5.3 Mekanisme Timer

Timer adalah komponen kritis yang menentukan kapan sesi ujian berakhir. Berikut spesifikasi mekanisme timer yang berlaku, termasuk perilaku saat koneksi terputus dan tindakan otomatis saat waktu habis.

  • Submit OtomatisSaat timer = 0, ujian otomatis disubmit; nilai MCQ langsung dihitung
  • Notifikasi (perlu ditambah)Peringatan visual saat sisa 10 menit (warna kuning) dan 5 menit (warna merah)

5.4 Penilaian MCQ — Sudah Otomatis

Penilaian berjalan di simpan-hasil.php: nilai dihitung berdasarkan persentase jawaban benar (is_correct = 1 di tabel jawaban), disimpan ke tabel nilai. Jika nilai ≥ nilai_kelulusan, peserta dinyatakan lulus.

5.5 Penilaian Essay — Gap Kritis

Gap Saat Ini: Ujian essay (tipe_soal = 2) menyimpan nilai awal 0. Tidak ada antarmuka untuk operator input nilai essay. Fitur penilaian essay manual harus dibangun segera sebelum ujian essay berikutnya.

Yang perlu dibangun:

  • Halaman admin: daftar peserta essay dengan status "Belum Dinilai / Sudah Dinilai"
  • Tampilkan jawaban essay yang sudah ditulis peserta di tabel hasil.essay
  • Form input nilai (0–100) per peserta per soal essay
  • Update otomatis tabel nilai setelah operator simpan

8.1 Dokumentasi Teknis — Instalasi & Konfigurasi

Panduan ini ditujukan untuk teknisi atau administrator server yang bertanggung jawab atas instalasi, pemeliharaan, dan pengembangan sistem.

A. Persyaratan Sistem

  • Web ServerApache 2.4+ atau Nginx 1.18+; direkomendasikan Apache dengan mod_rewrite aktif
  • PHPPHP 7.4 atau lebih baru; ekstensi wajib: mysqli, session, mbstring, gd
  • DatabaseMySQL 5.7+ atau MariaDB 10.3+
  • Browser KlienChrome 90+, Firefox 88+, Edge 90+; JavaScript harus aktif
  • RAM ServerMinimum 2 GB; disarankan 4 GB untuk 50+ peserta bersamaan
  • DiskMinimum 5 GB untuk aplikasi, database, dan backup

B. Langkah Instalasi — Windows (XAMPP)

Cocok untuk komputer lokal, lab ujian, atau server kantor berbasis Windows. Menggunakan XAMPP yang sudah menyertakan Apache, PHP, dan MySQL dalam satu paket.

  1. Download & install XAMPP dari https://www.apachefriends.org — pilih versi yang menyertakan PHP 7.4 atau lebih baru. Jalankan installer dan install ke C:\xampp\ (default)
  2. Jalankan XAMPP Control Panel → klik Start pada baris Apache dan MySQL — kedua status harus berubah menjadi hijau
  3. Salin folder aplikasi ke direktori htdocs:
    REM Salin seluruh folder ujian ke dalam htdocs
xcopy /E /I C:\sumber\ujian C:\xampp\htdocs\ujian

REM Atau cukup drag-and-drop folder "ujian" ke C:\xampp\htdocs\ menggunakan Explorer
  4. Buat database via phpMyAdmin:
    1. Buka browser, akses http://localhost/phpmyadmin
    2. Klik tab Databases → ketik nama database: db_ujian_online → pilih collation utf8mb4_unicode_ci → klik Create
    3. Klik database db_ujian_online di panel kiri → klik tab Import
    4. Klik Choose File → pilih file db_ujian_online.sql dari folder aplikasi → klik Go
  5. Konfigurasi koneksi database — buka file C:\xampp\htdocs\ujian\config\database.php dengan Notepad atau editor teks: 
    // Untuk XAMPP, password MySQL default kosong (tidak perlu diisi)
$host     = "localhost";
$user     = "root";
$password = "";               // XAMPP default: kosong
$db       = "db_ujian_online";
$kon = mysqli_connect($host, $user, $password, $db);
mysqli_set_charset($kon, "utf8mb4");
  6. Aktifkan mod_rewrite di Apache XAMPP:
    1. Buka XAMPP Control Panel → klik Config di baris Apache → pilih httpd.conf
    2. Cari baris #LoadModule rewrite_module → hapus tanda # di depannya
    3. Simpan file → kembali ke XAMPP Control Panel → klik Stop lalu Start Apache
  7. Uji akses dengan membuka http://localhost/ujian/login.php di browser
Tips XAMPP: Jika port 80 sudah dipakai aplikasi lain (misal IIS atau Skype), ubah port Apache ke 8080 via XAMPP Control Panel → Config → httpd.conf → cari Listen 80 ganti ke Listen 8080. Akses menjadi http://localhost:8080/ujian/.

C. Langkah Instalasi — Linux / Server (Apache Langsung)

Untuk server Linux Ubuntu/Debian yang sudah terpasang Apache dan MySQL secara terpisah (tanpa XAMPP).

  1. Salin file aplikasi ke direktori web server: 
    cp -r /sumber/ujian /var/www/html/ujian
chown -R www-data:www-data /var/www/html/ujian
  2. Buat database dan import skema: 
    mysql -u root -p -e "CREATE DATABASE db_ujian_online CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -u root -p db_ujian_online < db_ujian_online.sql
  3. Konfigurasi koneksi database di config/database.php: 
    // Sesuaikan dengan kredensial server Anda
$host     = "localhost";
$user     = "root";
$password = "password_anda";  // Ganti dengan password MySQL Anda
$db       = "db_ujian_online";
$kon = mysqli_connect($host, $user, $password, $db);
mysqli_set_charset($kon, "utf8mb4");
  4. Atur izin direktori untuk upload gambar soal: 
    chmod 775 /var/www/html/ujian/img/soal/
chown www-data:www-data /var/www/html/ujian/img/soal/
  5. Aktifkan mod_rewrite di Apache: 
    a2enmod rewrite
systemctl restart apache2
  6. Uji akses dengan membuka http://[IP-SERVER]/ujian/login.php di browser.

8.2 User Manual — Peserta Ujian

Panduan ini ditujukan untuk peserta (ASN/PNS kataloger) yang akan mengikuti ujian kompetensi melalui sistem CAT PUSKOD BALOGHAN KEMHAN.

Sebelum Mulai: Pastikan Anda menggunakan browser Chrome, Firefox, atau Edge versi terbaru. Koneksi internet/intranet harus stabil. Matikan pop-up blocker. Siapkan NIP dan password yang telah diberikan oleh operator.

Langkah 1 — Login ke Sistem

  1. Buka browser dan akses alamat: http://[alamat-server]/ujian/
  2. Pada kolom Username, masukkan NIP Anda (contoh: 197607242001121001)
  3. Pada kolom Password, masukkan password yang telah diberikan operator
  4. Klik tombol MASUK
  5. Jika berhasil, Anda akan langsung diarahkan ke halaman ujian atau dashboard peserta
Gagal Login? Pastikan NIP diketik tanpa spasi dan tanpa tanda hubung. Jika tetap gagal setelah 3 kali percobaan, hubungi operator/admin untuk reset password.

Langkah 2 — Memahami Dashboard Peserta

Setelah login, Anda akan melihat daftar ujian yang tersedia. Setiap kartu ujian menampilkan:

  • Judul ujian — nama sesi ujian yang diikuti (misal: "Ujian Kompetensi Ahli Madya")
  • Tanggal & waktu — jadwal pelaksanaan ujian
  • Durasi — lama waktu ujian dalam menit
  • Status — Aktif (dapat dikerjakan), Menunggu (belum saatnya), atau Selesai

Langkah 3 — Memulai Ujian

  1. Klik tombol Kerjakan pada sesi ujian yang berstatus Aktif
  2. Baca halaman briefing dengan seksama: jumlah soal, durasi, dan aturan ujian
  3. Klik Mulai Ujian — timer langsung berjalan sejak tombol ini diklik
  4. Halaman soal pertama akan tampil secara otomatis
Perhatian: Setelah klik "Mulai Ujian", timer tidak dapat dihentikan atau dijeda. Pastikan Anda siap sebelum menekan tombol tersebut.

Langkah 4 — Mengerjakan Soal Pilihan Ganda (MCQ)

  1. Baca soal dengan teliti yang tampil di bagian tengah layar
  2. Klik salah satu pilihan jawaban (A, B, C, atau D) — pilihan yang dipilih akan berubah warna menjadi merah
  3. Jawaban tersimpan otomatis saat Anda pindah ke soal berikutnya (tidak perlu klik Simpan)
  4. Gunakan tombol Berikutnya → untuk lanjut, atau ← Sebelumnya untuk kembali
  5. Klik nomor soal di panel kiri untuk langsung melompat ke soal tertentu
  6. Nomor soal berwarna hijau = sudah dijawab; abu = belum dijawab

Langkah 5 — Mengerjakan Soal Essay

  1. Pada soal essay, area teks akan muncul di bawah pertanyaan
  2. Ketik jawaban Anda langsung di kotak teks yang tersedia
  3. Jawaban essay juga tersimpan otomatis saat berpindah soal
  4. Anda dapat kembali ke soal essay kapan saja selama ujian berlangsung untuk melengkapi atau mengubah jawaban

Langkah 6 — Review & Mengumpulkan Jawaban

  1. Klik tombol Selesai & Kumpulkan di pojok kanan bawah (atau saat timer habis, otomatis dikumpulkan)
  2. Halaman review menampilkan seluruh nomor soal — periksa apakah ada yang masih berwarna abu (belum dijawab)
  3. Klik nomor soal mana pun untuk kembali menjawab jika masih ada waktu
  4. Jika sudah yakin, klik Kumpulkan Jawaban
  5. Konfirmasi akan muncul — klik Ya, Kumpulkan untuk finalisasi. Jawaban tidak dapat diubah setelah dikumpulkan.
Penting: Jika waktu habis dan Anda belum mengumpulkan secara manual, sistem akan mengumpulkan jawaban secara otomatis. Semua jawaban yang sudah tersimpan tetap akan dinilai.

Langkah 7 — Melihat Hasil Ujian

  1. Setelah submit, halaman hasil ujian akan tampil otomatis
  2. Nilai ujian MCQ ditampilkan langsung dalam bentuk angka (0–100)
  3. Status Lulus ditampilkan jika nilai ≥ passing grade; Tidak Lulus jika di bawahnya
  4. Untuk ujian essay, nilai akan tampil setelah operator menyelesaikan penilaian manual
  5. Klik Cetak Hasil untuk mencetak atau menyimpan hasil ujian Anda

8.3 User Manual — Admin & Operator

Panduan ini ditujukan untuk admin dan guru/operator yang mengelola seluruh proses ujian, mulai dari pembuatan soal hingga penerbitan hasil.

A. Login sebagai Admin / Operator

  1. Buka http://[alamat-server]/ujian/login.php
  2. Masukkan username dan password operator (bukan NIP peserta)
  3. Setelah login, Anda masuk ke panel admin dengan sidebar menu di sebelah kiri

B. Mengelola Data Peserta (Siswa)

Menu: Sidebar → Siswa/Peserta

  • Tambah peserta baru: Klik tombol Tambah → isi NIP, nama, username, password → Simpan
  • Edit peserta: Klik ikon edit pada baris peserta → ubah data yang diperlukan → Simpan
  • Daftarkan peserta ke sesi ujian: Buka menu Peserta → pilih sesi ujian → centang peserta → Daftarkan
  • Reset password: Klik ikon edit → kosongkan kolom password lama → isi password baru → Simpan

C. Mengelola Mata Pelajaran / Bidang Kompetensi

Menu: Sidebar → Mapel

  • Setiap sesi ujian terikat ke satu mata pelajaran (bidang kompetensi), contoh: "Kodifikasi NSN", "Identifikasi Materiil"
  • Klik Tambah Mapel → isi nama bidang kompetensi → Simpan
  • Mata pelajaran yang sudah memiliki sesi ujian aktif tidak boleh dihapus

  • Saat ujian selesai, klik Nonaktifkan agar peserta tidak dapat mengerjakan ulang
  • Status ujian terlihat di kolom "Status" dengan badge Aktif (hijau) atau Nonaktif (merah)

8.5 SOP Backup & Restore Database

Backup rutin melindungi data ujian dari risiko kehilangan akibat kerusakan server, kesalahan operasional, atau gangguan teknis lainnya.

Backup Manual

# Backup lengkap database — jalankan setelah setiap sesi ujian
mysqldump -u root -p db_ujian_online > /backup/ujian_$(date +%Y%m%d_%H%M).sql

# Kompres untuk menghemat ruang penyimpanan
mysqldump -u root -p db_ujian_online | gzip > /backup/ujian_$(date +%Y%m%d).sql.gz

Backup Otomatis (Cron Job)

# Edit crontab: crontab -e
# Backup setiap hari pukul 02.00 dini hari
0 2 * * * mysqldump -u root -pPASSWORD db_ujian_online | gzip > /backup/ujian_$(date +\%Y\%m\%d).sql.gz

# Hapus backup lebih dari 30 hari (opsional)
0 3 * * * find /backup/ -name "ujian_*.sql.gz" -mtime +30 -delete

Prosedur Restore

# 1. Buat database baru jika belum ada
mysql -u root -p -e "CREATE DATABASE db_ujian_online;"

# 2. Restore dari file SQL biasa
mysql -u root -p db_ujian_online < /backup/ujian_20260609.sql

# 3. Restore dari file terkompresi (.gz)
gunzip -c /backup/ujian_20260609.sql.gz | mysql -u root -p db_ujian_online

# 4. Verifikasi — cek jumlah tabel
mysql -u root -p -e "SHOW TABLES;" db_ujian_online
