3.3 Masalah Teknis Prioritas

Audit kode dan struktur database mengungkap beberapa masalah teknis yang harus ditangani sebelum sistem dikembangkan lebih lanjut. Masalah-masalah ini diurutkan berdasarkan tingkat risiko terhadap keamanan dan integritas data.

KRITIS — MD5 Password: Tabel admin, guru, siswa menyimpan password dengan MD5. MD5 sudah terbukti tidak aman (rainbow tables). Harus dimigrasi ke password_hash($pass, PASSWORD_BCRYPT).
PENTING — SQL Injection: Pola mysqli_real_escape_string() dipakai di beberapa tempat, namun perlu audit menyeluruh. Transisi ke prepared statements (MySQLi bind_param) untuk semua query dengan input user.
PENTING — Charset latin1: Tabel inti pakai latin1 — karakter unicode (nama dengan aksara khusus) bisa corrupt. Perlu migrasi ke utf8mb4 setelah backup penuh.
DESAIN — Soal Terikat ke Sesi: Kolom soal.id_ujian berarti soal hanya bisa dipakai satu sesi. Untuk bank soal reusable, perlu tabel relasi terpisah ujian_soal.

3.4 Query Migrasi yang Disarankan

Berikut adalah perintah SQL dan perubahan kode PHP yang dapat langsung dieksekusi oleh pengembang untuk menerapkan perbaikan yang diprioritaskan. Lakukan backup penuh sebelum menjalankan perintah ALTER TABLE.

-- 1. Migrasi password ke bcrypt (di login.php dan form create user)
-- GANTI:
$password = md5($_POST['password']);
-- MENJADI:
$password = password_hash($_POST['password'], PASSWORD_BCRYPT);
-- VERIFIKASI LOGIN:
password_verify($_POST['password'], $row['password'])

-- 2. Migrasi charset tabel kritis (jalankan setelah backup penuh!)
ALTER TABLE siswa  CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE guru   CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE admin  CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE ujian  CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE hasil  CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER TABLE nilai  CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 3. Tambah kolom tingkat kesulitan soal
ALTER TABLE soal ADD COLUMN tingkat_kesulitan
  ENUM('mudah','sedang','sulit') DEFAULT 'sedang';

3.5 Visi Teknis Backend

Pengembangan backend sistem CAT PUSKOD BALOGHAN KEMHAN difokuskan pada ketersediaan tinggi (high availability) dan integritas data yang mutlak. Mengingat peran kataloger yang krusial dalam kodifikasi materiil pertahanan, backend harus mampu menangani beban akses serentak saat periode ujian nasional berlangsung. Sistem mematuhi standar keamanan data instansi pemerintah — setiap request harus melewati lapisan otorisasi ketat dan enkripsi data transit guna mencegah intersepsi informasi sensitif.

3.6 Desain Relasional Lanjutan (ERD)

Database dirancang dengan normalisasi tingkat ketiga (3NF) untuk meminimalkan redundansi data:

  • kataloger_infoMenyimpan data demografi dan riwayat kompetensi peserta per NIP
  • bank_soalTerintegrasi dengan modul kategorisasi NSN (NATO Stock Number); mendukung pengacakan soal (shuffling) dinamis per peserta untuk menjamin objektivitas
  • sesi_ujianIndexing pada kolom nip dan session_id untuk mempercepat query pemantauan real-time
  • jawaban_auditAudit trail lengkap setiap perubahan jawaban; mendukung rekonstruksi histori pengerjaan
Strategi Penguncian (Optimistic Locking): Diterapkan pada tabel transaksi jawaban untuk mencegah race condition saat banyak peserta submit bersamaan — memastikan tidak ada data yang tertimpa secara tidak sengaja.

3.8 SOP Backup Database Terotomatisasi

Perlindungan data menggunakan skrip shell yang di-trigger oleh Cron Job setiap malam untuk memastikan backup konsisten tanpa mengunci tabel aktif:

# Backup otomatis tanpa lock tabel aktif
mysqldump --single-transaction --quick --lock-tables=false db_ujian_kataloger \
  | gzip > /storage/backup/db_cat_$(date +%Y%m%d_%H%M).sql.gz

File hasil backup otomatis diunggah ke penyimpanan terenkripsi eksternal (off-site) sebagai langkah mitigasi bencana sesuai Disaster Recovery Plan instansi.
