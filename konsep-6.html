6.3 Hardening .htaccess

File .htaccess yang sudah ada di root aplikasi dapat diperkuat dengan konfigurasi berikut untuk memaksa HTTPS, menambahkan security headers, dan memblokir akses langsung ke file konfigurasi sensitif.

# Tambahkan ke /var/www/html/ujian/.htaccess

# Force HTTPS
RewriteEngine On
RewriteCond %{HTTPS} off
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]

# Security headers
Header always set X-Content-Type-Options "nosniff"
Header always set X-Frame-Options "DENY"
Header always set X-XSS-Protection "1; mode=block"

# Blokir akses langsung ke config
RedirectMatch 403 /config/database\.php
Options -Indexes

6.4 Implementasi Bcrypt — Kode Migrasi Password

Penggantian MD5 dengan password_hash() adalah langkah kritis pertama. Berikut kode penggantian di login.php dengan standar keamanan modern:

// 1. BUAT AKUN BARU — gunakan bcrypt (ganti MD5 lama)
$hash = password_hash($password_input, PASSWORD_BCRYPT);
// Simpan $hash ke kolom password di tabel admin / guru / siswa

// 2. VERIFIKASI LOGIN — login.php (dengan prepared statement)
$stmt = $kon->prepare("SELECT id, nama, password FROM admin WHERE username = ?");
$stmt->bind_param("s", $_POST['username']);
$stmt->execute();
$row = $stmt->get_result()->fetch_assoc();

if ($row && password_verify($_POST['password'], $row['password'])) {
    session_regenerate_id(true);      // cegah session fixation
    $_SESSION['id_user']   = $row['id'];
    $_SESSION['nama_user'] = $row['nama'];
    header("Location: index.php?page=beranda");
    exit;
}
Strategi Migrasi Bertahap (Tanpa Downtime): Tambahkan kolom pwd_bcrypt VARCHAR(255) ke tabel. Saat pengguna berhasil login dengan hash MD5 lama, langsung hash ulang dengan bcrypt dan simpan ke kolom baru. Setelah 30 hari (semua akun aktif bermigrasi), hapus kolom MD5 lama — tanpa paksa reset semua password sekaligus.

6.5 Penerapan CSRF Token pada Form Kritis

CSRF token wajib ditambahkan pada semua form POST — terutama login, submit jawaban, dan form manajemen admin. Pola implementasinya seragam:

// Generate token — satu kali per sesi, taruh di awal halaman
if (empty($_SESSION['csrf_token'])) {
    $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
}

// Di form HTML — hidden input wajib ada di setiap form POST
echo '<input type="hidden" name="csrf_token" value="'
   . htmlspecialchars($_SESSION['csrf_token']) . '">';

// Di handler POST — validasi PERTAMA sebelum proses apapun
if (!isset($_POST['csrf_token']) ||
    !hash_equals($_SESSION['csrf_token'], $_POST['csrf_token'])) {
    http_response_code(403);
    die('Permintaan tidak valid — CSRF token mismatch.');
}

6.7 Kesimpulan

Audit keamanan terhadap sistem CAT PUSKOD BALOGHAN KEMHAN mengidentifikasi 7 kerentanan dengan tingkatan dari kritis hingga rendah. Temuan terpenting adalah penggunaan MD5 tanpa salt untuk hashing password dan query raw string yang rentan SQL injection — keduanya ada pada file login.php yang menjadi gerbang utama seluruh sistem.

Kabar baiknya, seluruh kerentanan yang ditemukan memiliki solusi teknis yang sudah mapan dan tidak memerlukan perombakan arsitektur. Migrasi ke bcrypt membutuhkan 1–2 hari kerja, penerapan prepared statements 1 hari, dan pengaktifan HTTPS bergantung pada ketersediaan sertifikat SSL di server. Dengan menerapkan kelima lapisan keamanan dalam arsitektur defense in depth yang sudah dirancang, sistem ini dapat beroperasi dengan standar keamanan yang memadai untuk pengelolaan data kompetensi personel Kementerian Pertahanan.
