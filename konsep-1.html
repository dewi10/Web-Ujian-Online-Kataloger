Analisis Kebutuhan Desain Sistem

Pendahuluan, latar belakang, tujuan, proses bisnis, stakeholder, kebutuhan fungsional & non-fungsional, desain sistem, basis data, antarmuka & pengujian

1.1 Pendahuluan

Dokumen ini merupakan analisis kebutuhan desain sistem untuk Aplikasi Computer Assisted Test (CAT) Ujian Kompetensi Kataloger yang dikelola oleh Pusat Kodifikasi Badan Logistik Pertahanan Kementerian Pertahanan Republik Indonesia (PUSKOD BALOGHAN KEMHAN). Analisis dilakukan berdasarkan kondisi aplikasi yang saat ini telah berjalan secara aktif, mencakup evaluasi fitur eksisting, identifikasi celah (gap), serta rekomendasi pengembangan dan penguatan sistem.

Jabatan Fungsional Kataloger merupakan jabatan karier Pegawai Negeri Sipil (PNS) yang melaksanakan tugas kegiatan kodifikasi materiil pertahanan berdasarkan sistem NATO Stock Number (NSN). Sebagai satu-satunya instansi National Codification Bureau (NCB) di Indonesia, PUSKOD BALOGHAN KEMHAN bertanggung jawab atas standar dan kualitas seluruh kataloger di lingkungan Kemhan dan TNI. Ujian kompetensi menjadi instrumen utama untuk memastikan standar tersebut terpenuhi secara objektif dan terukur.

1.2 Latar Belakang

Sebelum sistem CAT diimplementasikan, proses ujian kompetensi kataloger dilakukan secara konvensional yang mengandung sejumlah kelemahan: potensi subjektivitas penilaian, risiko kebocoran soal, ketidakefisienan administrasi, serta keterbatasan skalabilitas peserta. Kebutuhan akan sistem ujian yang objektif, terstandardisasi, dan dapat diselenggarakan secara bersamaan untuk banyak peserta mendorong pengembangan platform berbasis web ini.

Aplikasi CAT saat ini telah berhasil digunakan dalam penyelenggaraan lebih dari 110 sesi ujian kompetensi dengan ratusan peserta ber-NIP aktual dari berbagai satuan kerja (Satker) di lingkungan Kemhan. Seiring meningkatnya jumlah peserta dan kompleksitas kebutuhan, diperlukan analisis menyeluruh untuk mengidentifikasi area yang perlu diperkuat — terutama dari sisi keamanan data, kelengkapan fitur penilaian essay, dan perlindungan integritas ujian.

Dasar Hukum: Peraturan Menteri Negara Pendayagunaan Aparatur Negara tentang Jabatan Fungsional Kataloger; Peraturan Pemerintah tentang Pegawai Negeri Sipil; STANAG NATO terkait sistem kodifikasi NSN yang menjadi acuan kompetensi teknis.

1.3 Tujuan

Analisis ini bertujuan untuk:

  • Mendokumentasikan kondisi sistem saat ini — mencakup fitur yang sudah berjalan, struktur database aktual, dan alur proses ujian dari login hingga penerbitan nilai.
  • Mengidentifikasi kebutuhan fungsional yang belum terpenuhi — seperti penilaian essay manual, monitoring live peserta, dan fitur anti-kecurangan.
  • Memetakan kerentanan keamanan — termasuk sistem hashing password yang tidak aman (MD5) dan potensi celah SQL injection yang perlu segera ditangani.
  • Memberikan rekomendasi teknis terstruktur — berupa roadmap pengembangan bertahap yang dapat dijadikan acuan tim pengembang dan manajemen PUSKOD BALOGHAN KEMHAN.
  • Menjadi acuan pengujian dan penerimaan sistem (UAT) — dengan skenario uji yang konkret berdasarkan alur aplikasi nyata.
  • Menyediakan kerangka dokumentasi teknis dan user manual — agar sistem dapat dioperasikan, dipelihara, dan dikembangkan secara berkelanjutan.

1.4 Deskripsi Aplikasi Eksisting

Aplikasi Ujian Online PUSKOD BALOGHAN KEMHAN telah beroperasi sebagai platform Computer Based Test (CBT/CAT) untuk uji kompetensi Jabatan Fungsional Kataloger. Sistem dibangun di atas PHP Native dengan database MySQL (db_ujian_online), berjalan di server dengan root di C:\xampp\htdocs\ujian\ (akses via localhost/ujian/).

Nama Resmi: "Pusat Kodifikasi Badan Logistik Pertahanan Kemhan" — Jl. Jati No.1, Pondok Labu, Jakarta Selatan 12450. Menangani ujian kompetensi berbasis NIP untuk kataloger ASN/PNS di lingkungan KEMHAN dan TNI.

1.8 Kebutuhan Non-Fungsional

Selain fitur fungsional, sistem harus memenuhi standar kualitas teknis berikut agar dapat beroperasi secara handal, aman, dan nyaman digunakan oleh seluruh peserta dan operator ujian.

  • PerformaHalaman ujian load <2 detik; auto-save latency <500ms; mendukung semua peserta aktif bersamaan
  • Keamanan PasswordKRITIS Saat ini MD5 — harus segera migrasi ke password_hash() PHP (bcrypt)
  • Encoding DatabaseTabel inti masih latin1 — perlu migrasi ke utf8mb4 agar nama/teks unicode aman
  • KompatibilitasChrome, Firefox, Edge modern; desktop dan laptop; resolusi minimum 1024×768
  • BackupBackup database harian otomatis; prosedur restore terdokumentasi; uji restore tiap bulan
  • Keamanan JaringanAkses via HTTPS; RBAC ketat; enkripsi data sensitif; logging seluruh aktivitas pengguna
  • SkalabilitasTarget kapasitas 500 pengguna serentak; arsitektur mendukung penambahan server tanpa downtime

1.9 Analisis Proses Bisnis

Proses penyelenggaraan Ujian Kompetensi Kataloger mencakup serangkaian tahapan yang saling berkaitan dan harus didukung penuh oleh sistem CAT secara end-to-end. Tahapan tersebut adalah:

①Pendaftaran & Verifikasi Peserta
②Penyusunan & Validasi Soal
③Pembentukan Paket Soal
④Penjadwalan Ujian
⑤Pelaksanaan & Penilaian Otomatis
⑥Verifikasi Hasil
⑦Penerbitan Laporan & Arsip Digital

Digitalisasi seluruh tahapan ini mengurangi kesalahan manual, mempercepat penerbitan hasil, dan meningkatkan integritas serta akuntabilitas penyelenggaraan ujian kompetensi.

1.11 Gambaran Desain Sistem

Sistem CAT dirancang menggunakan arsitektur tiga lapis (three-tier architecture) yang memisahkan lapisan presentasi, logika bisnis, dan penyimpanan data secara jelas.

🖥️
Client Web
Browser peserta & admin — menampilkan UI, mengirim request HTTP/HTTPS
⚙️
Application Server
PHP Native di XAMPP — memproses logika ujian, autentikasi, kalkulasi nilai
🗄️
Database Server
MySQL — menyimpan soal, jawaban, peserta, hasil, log aktivitas

Modul-modul internal saling berkomunikasi melalui include/require PHP. API endpoint disiapkan untuk kebutuhan integrasi masa depan dengan sistem kepegawaian (SIMPEG) maupun sistem lain di lingkungan Kemhan bila diperlukan.

1.13 Antarmuka & Rencana Pengujian

Antarmuka sistem terdiri dari beberapa halaman utama yang dirancang untuk kemudahan penggunaan dan efisiensi proses ujian:

  • Dashboard Admin/Operator — manajemen sesi, soal, peserta, dan laporan
  • Dashboard Peserta — daftar ujian tersedia dan riwayat ujian selesai
  • Halaman Ujian (fullscreen) — tampilan soal, timer countdown, navigasi antar soal
  • Halaman Monitoring Ujian — pantau peserta aktif secara real-time (direncanakan)
  • Laporan & Ekspor — grafik statistik, ekspor PDF dan Excel per sesi/per peserta

Rencana pengujian sistem mencakup: unit testing per modul, integration testing antar modul, system testing end-to-end, UAT bersama pengguna nyata, load testing untuk simulasi 500 pengguna serentak, security testing (penetration test), dan disaster recovery testing. Dokumen ini menjadi dasar penyusunan SRS, UML, ERD, SOP, dan implementasi teknis selanjutnya.
