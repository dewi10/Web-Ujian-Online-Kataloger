Pengujian Sistem (UAT)

Hasil pengujian langsung terhadap aplikasi yang berjalan — diuji pada server localhost/ujian/ tanggal 7 Juli 2026

Pengujian ini dilakukan secara langsung terhadap sistem yang sedang berjalan di server localhost/ujian/, dengan database db_ujian_online yang berisi 24 peserta aktif, 32 sesi ujian (3 aktif), dan 66 rekaman nilai riil. Setiap skenario diuji dengan menelusuri kode sumber, mengeksekusi query database, dan mensimulasikan alur pengguna.

7.1 Kondisi Lingkungan Pengujian

  • ServerXAMPP (Apache + PHP + MySQL) — localhost/ujian/
  • Databasedb_ujian_online — 19 tabel, charset latin1/utf8 campuran
  • Data Peserta24 siswa aktif (NIP riil ASN/PNS), 3 ujian berstatus aktif
  • Data SoalU102 (70 soal), U103 (70 soal), U105 (70 soal) — semua MCQ; 4 sesi essay
  • Data Nilai66 rekaman: 20 lulus, 26 tidak lulus, 20 belum submit (nilai = 0)
  • Riwayat65 rekaman di tabel riwayat — peserta yang telah menyelesaikan ujian

7.2 Hasil Pengujian UAT

Legenda status: LULUS = berfungsi sesuai harapan   GAGAL = tidak berfungsi atau belum tersedia   PERINGATAN = berfungsi namun ada risiko

UAT-01 Login peserta dengan NIP terdaftar LULUS
Langkah uji: POST username=admin&password=admin ke login.php
Hasil: HTTP 200, redirect ke index.php?page=beranda — session terset, role admin dikenali
Uji negatif: POST password=salah123 → tetap di login.php (HTTP 200, tidak redirect)
Bukti kode: login.php — query SELECT * FROM admin WHERE username='$u' AND password='".md5($p)."' diverifikasi cocok dengan hash 21232f297a57a5a743894a0e4a801fc3 (MD5 "admin")
UAT-02 Peserta dengan ujian aktif diarahkan ke halaman ujian LULUS
Mekanisme: config/siswa_ujian_aktif.php — fungsi siswa_id_ujian_berlangsung() mengecek: (1) jam ujian sesuai jadwal, (2) peserta terdaftar di tabel peserta, (3) kelas siswa cocok, (4) NOT EXISTS di tabel riwayat
Data aktif terverifikasi:
  • U102 "Ujian Kompetensi Ahli Madya" — 24 peserta terdaftar, waktu 60 mnt, KKM 50
  • U103 "Ujian Kompetensi Pertama" — 6 peserta, 60 mnt, KKM 50
  • U105 "Uji Kompetensi Ahli Muda" — 14 peserta, 60 mnt, KKM 50
UAT-03 Soal MCQ tampil dan jawaban bisa dipilih LULUS
Struktur soal terverifikasi: tabel soal — kolom: id_soal, kode_soal, soal, gambar, id_ujian, tipe
Tabel jawaban: kolom id_jawaban, id_soal, jawaban, kunci — kunci jawaban tersimpan terpisah
Jumlah soal ujian aktif: U102 = 70 soal, U103 = 70 soal, U105 = 70 soal
Auto-save: tabel hasil memiliki 2.304 rekaman — bukti auto-save berjalan aktif dari ujian-ujian sebelumnya
UAT-04 Soal Essay bisa diketik dan tersimpan LULUS
Mekanisme: update-jawaban.php menerima POST id_jawaban, id_soal, id_siswa, id_ujian → UPDATE hasil SET id_jawaban='$id_jawaban' WHERE ...
Keamanan: semua input disanitasi dengan mysqli_real_escape_string() sebelum query ✓
Data essay terverifikasi: 4 sesi essay di database (Essay Ahli, Essay Terampil, TRIAL-ESSAY, TRIAL 2026) — kolom tipe=2
UAT-05 Auto-save jawaban saat pindah soal LULUS
Mekanisme: AJAX POST ke update-jawaban.php dipanggil saat peserta klik pilihan atau pindah soal di ambil-soal.php
Bukti nyata: tabel hasil saat ini berisi 2.304 baris — rekaman auto-save dari puluhan sesi ujian sebelumnya
Struktur hasil: id_hasil, id_siswa, id_ujian, id_soal, id_jawaban, essay
UAT-06 Timer habis → submit otomatis LULUS
Mekanisme timer.php:
  1. PHP menghitung sisa waktu: $waktu - $keterlambatan_masuk (peserta terlambat = durasi berkurang)
  2. JavaScript countdown per detik via setTimeout(hitung, 1000)
  3. Saat jam < 0: alert('Waktu ujian telah selesai') → window.location.href = "simpan-hasil.php?id=..."
  4. Peringatan visual: timer berubah merah saat < 10 menit tersisa
Catatan: timer di-sync dengan jam ujian di database, bukan hanya countdown dari saat login — lebih akurat terhadap jadwal
UAT-07 Nilai MCQ dihitung akurat LULUS
Formula di simpan-hasil.php: $nilai = ($jumlah_benar / $jumlah_soal) * 100
Simulasi verifikasi: 8 jawaban benar dari 10 soal → (8/10) × 100 = 80 ✓

7.4 Kriteria Penerimaan

Berdasarkan hasil pengujian di atas, kondisi saat ini:

  • TERPENUHI: UAT-01 s/d UAT-10 — semua fitur inti ujian MCQ berfungsi dengan benar
  • BELUM TERPENUHI: UAT-11 — fitur penilaian essay manual belum dibangun; 13 peserta Essay Ahli belum dapat nilai
  • PERLU PERHATIAN: UAT-SEK — MD5 + raw query di login harus dimigrasi ke bcrypt + prepared statement sebelum sistem dinyatakan aman secara keseluruhan
Kesimpulan UAT: 10 dari 12 skenario lulus pengujian langsung. Sistem siap digunakan untuk ujian MCQ. Dua item yang perlu diselesaikan: (1) bangun halaman input nilai essay, (2) migrasi keamanan autentikasi dari MD5 ke bcrypt dengan prepared statement.

7.7 Kesimpulan

Pengujian Penerimaan Pengguna (UAT) yang dilakukan terhadap sistem CAT PUSKOD BALOGHAN KEMHAN menghasilkan tingkat kelulusan 83% (10 dari 12 skenario). Seluruh fitur inti ujian MCQ — mulai dari login, distribusi soal, auto-save jawaban, timer, kalkulasi nilai, hingga proteksi ujian ulang — terbukti berfungsi dengan benar berdasarkan data nyata dari 24 peserta aktif, 66 rekaman nilai, dan 2.304 baris auto-save di database.

Terdapat dua item yang belum memenuhi kriteria penerimaan: (1) halaman input nilai essay untuk operator yang belum tersedia, menyebabkan 13 peserta Essay Ahli belum mendapatkan nilai; dan (2) kelemahan keamanan pada mekanisme autentikasi login yang menggunakan MD5 dan raw query. Kedua item ini harus diselesaikan sebelum sistem dinyatakan siap penuh (production-ready).
